## 1. 개요 및 목표

KFS_1 커널 위에 **커널 소유의 GDT(Global Descriptor Table)** 를 만들어 물리 주소
`0x00000800`에 설치하고 `lgdt`로 CPU에 등록한 뒤, **커널 스택을 사람이 읽기 좋게
출력하는 도구**(printk 기반 hexdump)를 구현한다.

지금까지 커널은 GRUB이 임시로 만들어 준 GDT 위에서 실행됐다. Multiboot 규약은
"GDTR이 유효하다고 보장하지 않으므로 세그먼트 레지스터를 다시 로드하려면 자기
GDT를 먼저 만들라"고 명시한다 — 이 과제가 그 작업이다.

**이 문서 범위의 목표 (mandatory)**
- null + 6개(Kernel Code/Data/Stack, User Code/Data/Stack) = 7엔트리 GDT
- GDT를 `0x00000800`에 런타임 직접 구축, `lgdt` + 세그먼트 리로드
- printk 폭 지정 확장(`%08x`, `%02x`) 후 커널 스택 hexdump 도구
- 기존 KFS_1 기능(부팅, VGA, selftest, "42") 무회귀 + 자동 테스트 갱신

**범위 결정**: 보너스(폴링 키보드 + 디버그 미니셸)는 mandatory 완성·검증 후
별도 단계로 진행 여부를 다시 결정한다(§12).

## 2. 과제 요구사항 (mandatory) 요약

`kfs2.pdf` V장 기준:

1. Global Descriptor Table을 생성(create)·채우고(fill)·커널에 링크(link)
2. GDT에 포함: Kernel Code / Kernel Data / Kernel stack / User code / User data / User stack
3. 작업물 10MB 이하 (KFS_1의 ISO ≤ 10MiB 검사 계승)
4. GDT를 BIOS에 선언 — 실제 의미는 `lgdt`로 CPU의 GDTR 레지스터에 등록(§8.4)
5. GDT는 주소 `0x00000800`에 배치
6. 이후: 커널 스택을 human-friendly하게 출력하는 도구 작성 (printk 활용 팁 명시)

**제약(kfs1.pdf에서 이월, IV장에서 재확인)**: i386 필수 / freestanding 플래그 /
호스트 라이브러리·호스트 `.ld` 파일 금지(`ld` 바이너리는 허용) / Makefile 필수 /
제출물 = 코드 + Makefile + 기본 가상 이미지(git 레포).

**보너스**(mandatory가 PERFECT할 때만 평가): 키보드 입력 전제의 디버그 미니셸
(print-kernel-stack, reboot, halt 등).

- `grub.cfg`: `menuentry "KFS-2"` (완료)

GDT/스택 작업은 컴파일 플래그·툴체인·ISO 규칙에 영향을 주지 않는다.

## 5. 아키텍처 & 부팅 흐름

```
[QEMU 전원]
   -> [BIOS] --ISO--> [GRUB]  (multiboot: 커널을 1MiB에 로드, 보호모드 전환)
   -> [boot.asm: _start]  esp = stack_top(.bss 16KiB), psABI 정렬, push magic/mbi
   -> [kernel.c: kernel_main]
        vga_init
        magic 검증 (0x2BADB002)
        gdt_init                    <- ★ KFS_2 신규
          ├─ 0x00000800에 7엔트리 직접 기록
          └─ gdt_flush: lgdt -> DS/ES/FS/GS=0x10, SS=0x18, far jmp 0x08 (CS)
        selftest (libk + VGA scroll + ★GDT sgdt/셀렉터 검증)
        multiboot 배너, printk 데모(★%08x/%02x 포함)
        print_kernel_stack          <- ★ KFS_2 신규 (esp~stack_top hexdump)
        "42" 배너
   -> cli; hlt 무한루프
```

**저메모리 지도** (GDT 위치의 근거):

```
0x00000000 ~ 0x000003FF   IVT (리얼모드 인터럽트 벡터)
0x00000400 ~ 0x000004FF   BDA (BIOS Data Area)
0x00000500 ~ 0x00007BFF   자유 영역  <- ★ 0x800이 여기
0x00007C00 ~              (부트섹터 관례 주소; GRUB 사용 후 무의미)
0x00100000 ~              커널 (.text .rodata .data .bss[스택 16KiB 포함])
```

쓰기 시점 안전성: `gdt_init`은 multiboot info를 역참조하기 전·후 어느 쪽이든
0x800 영역과 무관하지만(우리 커널은 mbi 주소를 출력만 하고 역참조하지 않음),
관례상 magic 검증 직후·다른 작업 전에 실행한다.

## 8. GDT 상세 설계 (핵심)

### 8.1 자료구조 (x86이 정한 8바이트 배치)

```c
struct gdt_entry {
    uint16_t limit_low;    /* limit 15:0  */
    uint16_t base_low;     /* base  15:0  */
    uint8_t  base_middle;  /* base  23:16 */
    uint8_t  access;       /* P(7) DPL(6:5) S(4) Type(3:0) */
    uint8_t  granularity;  /* G(7) D(6) L(5) AVL(4) limit 19:16 */
    uint8_t  base_high;    /* base  31:24 */
} __attribute__((packed));

struct gdt_ptr {           /* lgdt 피연산자 (GDTR에 들어갈 6바이트) */
    uint16_t limit;        /* GDT 전체 크기 - 1 = 7*8-1 = 55(0x37) */
    uint32_t base;         /* 0x00000800 */
} __attribute__((packed));
```

base/limit가 조각난 배치는 286(24-bit) → 386(32-bit) 호환성의 역사적 산물.
`__attribute__((packed))`는 컴파일러 패딩 삽입을 금지해 CPU가 기대하는
바이트 배치를 보장한다.

### 8.2 7엔트리 값 (전부 base=0, limit=0xFFFFF, granularity=0xCF)

| # | 셀렉터 | 세그먼트 | access | access 풀이 |
|---|---|---|---|---|
| 0 | 0x00 | null | 0x00 | CPU 필수. null 셀렉터 로드 시 사용 시점에 fault → 버그 조기 발견 |
| 1 | 0x08 | Kernel Code | **0x9A** | P=1, DPL=0, S=1, Type=1010(코드, 실행+읽기) |
| 2 | 0x10 | Kernel Data | **0x92** | P=1, DPL=0, S=1, Type=0010(데이터, 쓰기 가능) |
| 3 | 0x18 | Kernel Stack | **0x92** | 데이터형 동일, 역할 분리용 별도 엔트리(결정 로그 참조) |
| 4 | 0x20 | User Code | **0xFA** | 0x9A에서 DPL=3만 변경 |
| 5 | 0x28 | User Data | **0xF2** | 0x92에서 DPL=3만 변경 |
| 6 | 0x30 | User Stack | **0xF2** | 〃 |

- granularity `0xCF` = G=1(limit 단위 4KiB → 0xFFFFF ⇒ 4GiB), D=1(32-bit), L=0, AVL=0, limit 19:16=0xF.
- 셀렉터 값 = 인덱스×8 (하위 3비트는 TI=0(GDT), RPL=0; User 세그먼트도 커널이
  로드할 일이 없으므로 RPL=0 형태 상수만 정의).
- User 3종은 KFS_2에서 실사용처가 없다(유저랜드 진입은 TSS·iret 트램펄린이
  필요한 후속 과제 범위). 과제 요구에 따라 "자리를 미리 깔아두는" 정의다.

### 8.3 gdt.c 동작

```c
static struct gdt_entry *const gdt = (struct gdt_entry *)GDT_BASE;  /* 0x800 직접 */
static struct gdt_ptr gp;

gdt_init():
    gdt_set_gate(0, 0, 0, 0, 0);                      /* null */
    gdt_set_gate(1, 0, 0xFFFFF, 0x9A, 0xCF);          /* kernel code  */
    gdt_set_gate(2, 0, 0xFFFFF, 0x92, 0xCF);          /* kernel data  */
    gdt_set_gate(3, 0, 0xFFFFF, 0x92, 0xCF);          /* kernel stack */
    gdt_set_gate(4, 0, 0xFFFFF, 0xFA, 0xCF);          /* user code    */
    gdt_set_gate(5, 0, 0xFFFFF, 0xF2, 0xCF);          /* user data    */
    gdt_set_gate(6, 0, 0xFFFFF, 0xF2, 0xCF);          /* user stack   */
    gp.limit = sizeof(struct gdt_entry) * 7 - 1;      /* 55 */
    gp.base  = GDT_BASE;
    gdt_flush((uint32_t)&gp);
```

`gdt_set_gate`의 granularity 필드 조립 규칙(모호성 제거):
`entry.granularity = ((limit >> 16) & 0x0F) | (gran & 0xF0)` — gran 인자에서는
상위 4비트(G/D/L/AVL)만 취하고 하위 4비트는 limit 19:16에서 온다. 따라서
`limit=0xFFFFF, gran=0xCF`를 넘기면 최종 바이트는 0xCF가 된다.

### 8.4 gdt_flush.asm

```asm
global gdt_flush
gdt_flush:                 ; cdecl: gdt_flush(uint32_t gdt_ptr_addr)
    mov  eax, [esp+4]
    lgdt [eax]             ; GDTR <- {limit=55, base=0x800}
    mov  ax, 0x10          ; Kernel Data 셀렉터
    mov  ds, ax
    mov  es, ax
    mov  fs, ax
    mov  gs, ax
    mov  ax, 0x18          ; Kernel Stack 셀렉터 (base 0 → esp 그대로 유효)
    mov  ss, ax
    jmp  0x08:.flush       ; CS는 mov 불가 → far jump가 CS 리로드 유일 수단
.flush:
    ret                    ; 스택 불변이므로 정상 복귀
```

- `lgdt`는 GDTR에 "표의 위치·크기"를 적재할 뿐이다. 효력은 세그먼트 레지스터를
  **다시 로드하는 순간** 각 레지스터의 히든 캐시(descriptor cache)가 새 GDT에서
  채워지며 발생한다. pdf의 "declare to the BIOS"는 이 `lgdt`를 뜻하는 느슨한 표현.
- 인터럽트는 GRUB 인계 시점부터 비활성(IF=0)이며 커널이 `sti`를 실행하지 않으므로
  리로드 시퀀스 중 인터럽트 위험은 없다.

## 9. 스택 덤프 도구 상세 설계

### 9.1 printk 확장 (선행 작업)

- 파서: `%` 뒤에서 `0` 플래그 → 10진 폭(누적) → 변환 문자 순으로 소비.
  `print_unsigned(n, base)`를 `(n, base, width, pad)`로 확장, 자릿수 부족분을
  pad 문자로 선행 출력. `%d/%u/%x` 공통 적용, 미지원 지시자 fallback 동작 유지.
- 표준 printf 문법 내 확장이므로 `printk.h`의 `__attribute__((format(printf,1,2)))`
  컴파일 타임 검증이 계속 동작한다.
- printk 데모 줄 확장: `%08x`(0xC0FFEE → `00c0ffee`), `%02x`(0xF → `0f`) 케이스
  추가 → boot_test가 assert할 결정적 문자열.

### 9.2 dump_hex / print_kernel_stack

```
void dump_hex(const void *addr, uint32_t len);
void print_kernel_stack(void);
```

- 행 포맷(76칸 ≤ 80칸 — boot_test "기대 문자열은 한 행 안" 규칙 충족):

```
AAAAAAAA  XX XX XX XX XX XX XX XX XX XX XX XX XX XX XX XX |aaaaaaaaaaaaaaaa|
(주소8)(공백2)(바이트 16개 각 "XX " 형식 48칸)(|)(ASCII 16칸: 0x20~0x7E만, 나머지 '.')(|)
= 8 + 2 + 48 + 1 + 16 + 1 = 76칸. 파이프 바로 앞 공백은 마지막 바이트의 후행 공백 1개다.
```

- `print_kernel_stack()`: 인라인 asm `mov %%esp, %0`으로 현재 esp 획득 →
  시작 주소를 16바이트 경계로 내림 정렬 → `stack_top`(boot.asm export)까지 덤프.
  헤더 1행 출력: `kernel stack: esp=%08x top=%08x size=%u bytes`.
  의미 정의: `size`는 실사용량(esp~top)이고, 덤프 자체는 행 정렬 때문에 esp보다
  최대 15바이트 아래(16바이트 경계)에서 시작할 수 있다 — 정렬은 4바이트 값
  (canary 포함)이 행 경계에 걸리지 않게 하는 장치이므로 의도된 동작이다.
- 테스트 마커: kernel_main이 `volatile uint32_t stack_canary = 0x2BADB002`를
  심어 덤프에 리틀엔디언 바이트열 **`02 b0 ad 2b`** 가 결정적으로 나타나게
  한다(volatile이 실제 스택 슬롯 기록을 강제). `_start`가 push한 magic도 보통
  같은 패턴을 남기지만 -O2에서 인자 슬롯 재사용 가능성이 있어 보장은 canary가
  담당한다.
- 예상 출력량: kernel_main 시점 esp ≈ stack_top-32 부근 → 헤더 + 2~3행.
  화면(25행)을 넘지 않아 스크롤로 밀려나지 않는다.

## 10. 데이터 흐름 & 에러 처리

- KFS_1의 규칙 유지: magic 검증 실패 시 빨간 PANIC 출력 후 hlt 루프,
  커널은 return 금지, VGA 25행 초과 시 스크롤.
- **GDT selftest 실패**: 기존 `SELFTEST FAIL: <name>` 규약 재사용(빨간색 출력,
  boot_test가 이 문자열을 발견하면 무조건 실패). 통과 시 `kfs: gdt ok` 출력.
- gdt_flush 시퀀스가 잘못되면(예: far jump 누락, 잘못된 셀렉터) CPU가 triple
  fault로 리부팅 → QEMU `-no-reboot` 옵션(기존 boot_test에 있음) 덕분에 화면이
  비어 있는 상태로 테스트가 실패한다. 즉 "GDT 후 부팅 생존" 자체가 1차 검증.

## 11. 검증 방법

| 확인 항목 | 방법 |
|---|---|
| GDT 로드 후 부팅 생존 | `make test` 기존 assertion 전부 유지(" 42 ", "selftest ok", SCRL 등) |
| GDTR base==0x800, limit==55 | selftest에서 `sgdt` 판독 assert → `kfs: gdt ok` → boot_test `"gdt ok"` |

| 스택 덤프 | 헤더(`kernel stack:`)와 magic 바이트열 `"02 b0 ad 2b"` assert |
| 10MB 이하 | 기존 ISO 크기 검사 유지 (KFS_1 기준 5.1MB, 소스 추가분은 KB 단위) |
| 회귀 없음 | 뼈대 이식 시점의 9-assertion 통과 상태가 기준선 |
| (선택 확장) | QEMU 모니터 `xp /56bx 0x800` 물리 덤프, `info registers`의 GDTR 라인 — 공백/포맷이 QEMU 버전에 결합되므로 정규식 흡수 필요. 커널 내부 검증이 충분하면 생략 가능 |

## 13. 열린 질문 / 리스크

- **출력 순서와 스크롤**: selftest의 scroll_exercise(SCRL 30행)가 화면을 밀어내므로
  GDT/스택 관련 assert 문자열은 전부 selftest **이후** 출력 순서를 지켜야 한다
  (§5의 시퀀스가 이를 보장; 구현 시 순서 변경 금지).
- **BOOT_WAIT**: Apple Silicon(Rosetta+TCG)에서 부팅이 느리면 기본 6초가 부족할 수
  있음 — 실패 시 `BOOT_WAIT=10 make test`로 재검. 클러스터(x86 네이티브)는 무관.
- **printk 확장 회귀**: 기존 `%x` 무패딩 출력("2badb002" 등 기존 assert)이 폭 미지정
  시 동일하게 유지되는지 확인 필요(파서 변경의 회귀 지점).
- **kfs.iso 제출 정책**: KFS_1은 최종 ISO를 `git add -f`로 커밋했다(과제의 "기본
  가상 이미지" 요구). kfs2.pdf도 동일 요구 — 최종 제출 직전에 같은 방식 적용 예정.

## 부록 A. Defense 예상 질문 (학습 포인트)

| 질문 | 답의 골자 |
|---|---|
| GDT가 왜 필요한가? | 보호모드 x86의 모든 메모리 접근은 세그먼트를 경유한다. GDT는 각 세그먼트의 base/limit/권한(DPL, 실행/쓰기)을 정의하는 표. 지금까지는 GRUB의 임시 GDT를 썼고, multiboot 규약이 "직접 만들라"고 요구한다 |
| 왜 0x800에 두나? | 과제 지정. 그 주소가 안전한 이유는 실모드 메모리 지도(IVT 0x000, BDA 0x400 다음의 자유 영역 0x500~0x7BFF)에 있고 커널(1MiB)과 안 겹치기 때문 |
| 왜 linker가 아니라 런타임에 설치하나? | GRUB(multiboot)은 1MiB 미만으로 로드를 거부하므로 ELF 섹션으로 0x800에 실을 수 없다. 커널이 부팅 후 직접 그 주소에 써 넣는다 |
| lgdt는 무엇을 하나? | GDTR에 표의 주소·크기(6바이트)를 적재할 뿐. 효력은 세그먼트 레지스터 리로드 시 발생. CS는 mov 불가라 far jump 필요 |
| 6개라더니 왜 엔트리가 7개인가? | CPU가 0번 null 디스크립터를 강제한다. null 셀렉터 사용 시 fault → 초기화 안 된 셀렉터 버그를 조기 검출하는 안전장치 |
| 스택 세그먼트에 왜 expand-down을 안 썼나? | limit 의미가 반전되어 flat 값과 조합하면 유효 범위가 0이 되는 함정. flat 모델에선 일반 데이터형이 표준 |
| GDT 로드 후 esp가 왜 그대로 유효한가? | 새 SS도 base 0(flat)이라 "SS:esp가 가리키는 물리 위치"가 변하지 않는다 |
| 스택은 어디에 있고 어느 방향으로 자라나? | boot.asm이 .bss에 잡은 16KiB(stack_bottom~stack_top). push 시 esp 감소(높은 주소→낮은 주소). 덤프는 esp~stack_top = "현재 쌓인 내용" |
| User 세그먼트는 쓰이나? | 정의만. ring3 진입은 TSS·iret이 필요한 후속 과제. DPL=3 값만 미리 올바르게 설정 |
| selftest에서 CS==0x08 확인이 far jump가 실행됐다는 증거인가? | 아니다(중요). GRUB도 우리를 CS=0x08, DS=0x10으로 진입시키므로 이 값은 far jump 없이도 우연히 일치한다. 히든 디스크립터 캐시는 직접 읽을 수 없다. 실제 리로드를 증명하는 유일한 check는 SS==0x18 — GRUB이 절대 쓰지 않는 값이라 gdt_flush의 세그먼트 리로드가 실행됐을 때만 성립한다. 그래서 selftest에서 SS check를 제거하면 안 된다 |
